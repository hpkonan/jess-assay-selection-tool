> Personas are based on field experience with Jess users and support teams. They are hypotheses to be confirmed through pilot interviews (R3).

---

## P1 — Field Application Scientist ("the field expert")

| | |
|---|---|
| **Context** | Spends several days a week on customer sites for demos, installations and trainings; also answers follow-up questions by email and phone |
| **Expertise** | Expert in Simple Western; knows the decision logic but must explain it again and again |
| **Device and setting** | Laptop or phone, often in a lab or meeting room with the customer; sometimes limited connectivity |
| **Job-to-be-done** | "When a customer asks how to measure two proteins on Jess, I want to give a clear, consistent answer on the spot, so that the customer succeeds and trusts our advice." |
| **Pains** | Repeating the same explanation; inconsistent advice between colleagues; checking reagent references in several documents; writing follow-up emails |
| **Gains** | Answer in front of the customer in under 2 minutes; a copyable recommendation for the follow-up email; a teaching aid during trainings |
| **Success looks like** | Fewer follow-up questions; customers designing their second assay alone |

---

## P2 — Jess end user ("the bench scientist")

| | |
|---|---|
| **Context** | Researcher, PhD student, post-doc or technician running protein expression studies (e.g. phospho vs total protein, loading control + target) |
| **Expertise** | Knows western blotting; variable experience with Jess-specific options (fluorescence channels, RePlex) |
| **Job-to-be-done** | "When I need to quantify two proteins from a precious sample, I want to know which Jess workflow and reagents to use, so that I get publishable data without repeating the run." |
| **Pains** | Uncertainty between multiplex and RePlex; fear of wasting sample and cartridges; unclear which secondary antibodies are compatible; jargon |
| **Gains** | Clear recommendation with reasons; reagent list to order; tips on probing order |
| **Constraints** | Limited sample; budget; may not know the exact apparent MW of a target on Jess yet |

---

## P3 — Technical Support specialist ("the remote troubleshooter")

| | |
|---|---|
| **Context** | Handles customer cases remotely (email, phone, tickets) |
| **Job-to-be-done** | "When a customer asks a design question, I want to answer it quickly and consistently, so that I can spend my time on real troubleshooting." |
| **Pains** | Repetitive design questions; incomplete information from the customer; risk of contradicting what the FAS said |
| **Gains** | A shared reference with the FAS team; a structured set of questions to ask the customer; a clean escalation path for unusual combinations |

---

## P4 — Core facility / lab manager ("the standardizer")

| | |
|---|---|
| **Context** | Manages a shared Jess instrument used by many researchers |
| **Job-to-be-done** | "When new users book the instrument, I want them to design multi-target assays the same validated way, so that runs succeed and instrument time is not wasted." |
| **Pains** | Training many users with different levels; repeated mistakes (multiplexing without validation, co-migrating targets in chemi) |
| **Gains** | A link to share during onboarding; consistent rules across users |

---

## Persona priority

| Priority | Persona | Rationale |
|---|---|---|
| Primary (Stages 0–2) | P1, P3 | Internal users; immediate time savings; safe environment for validating the content |
| Secondary (Stage 3) | P2, P4 | Reached directly only after scientific and brand endorsement |
